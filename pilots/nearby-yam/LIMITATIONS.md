# Limitations

This pilot is evidence of deterministic path-boundary behavior. It is not yet
evidence of workflow value.

## What It Supports

- ARC matched real repository paths against frozen allowed/excluded globs.
- All five explicit excluded-path changes were blocked.
- The two allowed-path changes were not incorrectly blocked.
- Incomplete provenance and missing validation evidence prevented `Pass`.
- Repeating the run produced the same verdicts.

## What It Does Not Support

- The changes were not generated by an AI coding agent.
- The changes were not GitHub pull requests.
- ARC was not installed in Nearby_Yam's repositories.
- ARC was not configured as a required check.
- The pilot did not run repository tests or builds.
- The pilot did not measure review time, false-positive cost, or reviewer
  annoyance.
- The pilot does not prove code correctness, security, maintainability, or
  architectural quality.
- The pilot does not provide runtime write prevention. Hooks, permissions, or
  sandbox controls are needed to stop a file write before it happens.

## Provenance Caveat

The synthetic commits exist only in the local pilot clones, so their commit
SHAs cannot be fetched from the upstream repositories. The complete patches,
base SHAs, raw ARC logs, generated briefs, and packet checksums are published
here so the experiment can still be inspected.

## Next Validation

A proper customer pilot should:

1. Freeze a real assignment before coding.
2. Let an AI coding agent implement it.
3. Run ARC from provider-derived base/head SHAs.
4. Execute required commands inside the ARC check.
5. Make the ARC verdict a required GitHub check.
6. Ask whether the Trust Brief reduced review work or added noise.
